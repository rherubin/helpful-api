# Find-bugs report — 2026-08-07

Critical bugs found: **yes (2 new)**, fixed in this PR.

## Bugs & impact

### 1. Org-code directory leaked redeemable secrets → free premium
- **Where:** `routes/org-codes.js` `GET /api/org-codes` (app auth)
- **Trigger:** Any authenticated user lists org codes; response included `org_code`. Client then `PUT /api/users/:id` with `{ org_code }` to set `is_premium=true`.
- **Impact:** Privilege escalation / unpaid premium (and Hopeful org prompts) for every account that can log in.
- **Fix:** Strip `org_code` (and prompts) from non-admin list responses. Admins still receive full rows.

### 2. Pairing accept TOCTOU race exceeded `max_pairings`
- **Where:** `services/PairingService.acceptPairingByCode` / `models/Pairing.acceptPairingByPartnerCode`
- **Trigger:** One user concurrently `POST /api/pairing/accept` against two different pending partner codes while `max_pairings=1`. Both count checks saw 0 accepted pairings; both updates succeeded.
- **Impact:** Users could exceed the hard pairing cap (multi-partner state / product invariant break). Same class of race on restore.
- **Fix:** `acceptPairingByPartnerCodeAtomic` and `restorePairingAtomic` — transaction + `SELECT … FOR UPDATE` on member user rows, re-check counts, then accept/restore + leftover invite cleanup.
