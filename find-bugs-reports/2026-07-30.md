# Find-bugs report — 2026-07-30

## Critical bug found: yes

### Bug and impact

**Cross-user FCM device-token ownership** in `DeviceToken.registerDeviceToken`: the schema uniqueness is `(user_id, device_token)`, so the same FCM token string can be registered to multiple accounts. After an account switch on one phone (logout User A → login User B → register push token), both rows remain. Push fan-out then delivers to every owner of that token — including step-message pushes that embed reflection previews — leaking private couples-therapy content across accounts.

### Root cause

Registration upserted only within `(user_id, device_token)` and never reclaimed the token from other users. Dead-token pruning already deletes by raw token string globally, but live tokens were allowed to multi-subscribe.

### Fix and validation

- Before upsert, `DELETE FROM device_tokens WHERE device_token = ? AND user_id <> ?` so registration reclaims the device for the current user.
- Added `runTokenReclaimTests` in `tests/device-tokens-test.js` covering A→B account-switch reclaim.
- README note on single-account ownership.
- Validation: `node tests/device-tokens-test.js` → 40/40 passed (`TEST_MOCK_LLM=true`).
