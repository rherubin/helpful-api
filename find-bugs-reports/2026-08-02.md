## New bugs fixed in this change

### 1. Admin refresh always fails (`deleteTokenByUserId` missing)

- **Location:** `services/AdminAuthService.js` → `verifyAndRefreshTokens`
- **Trigger:** Admin calls `POST /api/admin/auth/refresh` with a valid refresh token
- **Impact:** Always 401; newly inserted refresh row is orphaned. Repeat logins accumulate rows; `getTokenByUserId` is nondeterministic across multiples
- **Root cause:** Called nonexistent `refreshTokenModel.deleteTokenByUserId()` *after* `issueTokensForAdminUser()`. Even the correctly named delete-by-user helper would wipe the just-created token if invoked after issue
- **Fix:** Delete admin refresh rows *before* issuing replacements; clear prior tokens on `loginAdmin` too

### 2. FCM `mismatched-credential` auto-prunes valid device tokens

- **Location:** `services/PushNotificationService.js` → `FCM_DEAD_TOKEN_CODES`
- **Trigger:** Deploy wrong/staging Firebase credentials (or FCM API misconfig) then send any push (`pairing_accepted`, step message, admin `push-test`, etc.)
- **Impact:** Valid `device_tokens` rows deleted for every affected user; push delivery silently stops until clients re-register
- **Root cause:** Config/project mismatch treated as a permanently dead token
- **Fix:** Remove `messaging/mismatched-credential` from the dead-token set; keep only true dead-token codes
