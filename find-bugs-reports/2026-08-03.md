# Find-bugs report — 2026-08-03 (UTC)

## Critical bug found: yes

### Bug and impact
Stripe webhook premium sync (`StripeBillingService.syncPremiumForUser`) set `users.is_premium` from Stripe subscription status alone. When a Stripe trial/subscription later canceled or failed, org-code and custom-org users lost premium even though they remained org-entitled — breaking auth/profile premium gates for those accounts.

Separately, when `STRIPE_SECRET_KEY` was unset the mock Stripe client accepted any non-empty `stripe-signature` and would apply forged `checkout.session.completed` events, allowing unauthenticated premium grants on a publicly reachable API.

### Root cause
1. `syncPremiumForUser` ignored the existing org entitlement model (`org_code_id` or complete custom org fields) that also writes `users.is_premium`.
2. Mock webhook verification only checked that a signature header was present, and mock mode activated automatically whenever the Stripe secret key was missing.

### Fix and validation
- Recompute premium as Stripe-active **OR** org-entitled before writing `is_premium`.
- Disable mock webhooks unless `TEST_MOCK_STRIPE=true` is explicitly set.
- Added regression coverage in `tests/stripe-billing-test.js` (`testOrgPremiumSurvivesStripeCancel`).
