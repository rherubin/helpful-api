# Find-bugs report — 2026-08-13 (UTC)

## Critical bugs found: yes (2 new)

### 1. Theme VARCHAR mismatch → partial program steps → stuck incomplete program

- **Location:** `services/BasePromptService.js` `validateProgramStructure`; `models/ProgramStep.js` `createProgramSteps`; `routes/programs.js` `runGenerationWithFollowUp` / `hasProgramSteps`
- **Trigger:**
  1. Create a program (LLM returns a validated payload)
  2. At least one day `theme` is 256–300 chars (previously allowed by the validator) **or** step insert fails mid-loop for any reason
  3. Earlier days commit; later days fail (`ER_DATA_TOO_LONG` under strict SQL mode, or connection error)
  4. Follow-up sees `hasProgramSteps === true` (any rows) and returns success without writing `generation_error`
  5. `POST /api/programs/:id/therapy_response` returns **409** because steps exist
- **Impact:** Data loss / user-facing breakage — couple is stuck with an incomplete program (e.g. 3 of 14 days), no `generation_error`, and no API retry path short of deleting the program
- **Root cause:** Validator allowed themes up to 300 while `program_steps.theme` is `VARCHAR(255)`; step inserts were non-transactional; “any steps exist” was treated as success
- **Why not a duplicate of open PRs #12–#17:** PR #16 covers regen poller CASCADE-before-success, sit-session abandoned/complete resurrection, and duplicate `(program_id, day)` races — not the validator/schema mismatch or partial-insert → follow-up false-success path on initial generation
- **Fix:** Cap theme validation at 255; make `createProgramSteps` transactional; only treat contiguous 7/14-day sets as complete for skip/409 decisions

### 2. Sit Session late generate demotes `in_session` → `bridge`

- **Location:** `models/PromptSession.js` `saveGeneratedContent`
- **Trigger:**
  1. Both preps complete → generation starts (`generation_status=running`)
  2. Client `PATCH`es `status` to `in_session` while waiting (optimistic / resumed session)
  3. Generation finishes and `saveGeneratedContent(..., status: 'bridge')` runs
- **Impact:** User-facing breakage — live Sit Session status is yanked back to `bridge` mid-experience (`current_phase` can stay advanced → inconsistent client state)
- **Root cause:** Unconditional `status = ?` on successful generate
- **Why not a duplicate of PR #16:** PR #16 preserves only `complete` / `abandoned` (terminal resurrection). Demoting an active `in_session` session is a separate active-session regression
- **Fix:** `status = IF(status IN ('complete','abandoned','in_session'), status, ?)`
