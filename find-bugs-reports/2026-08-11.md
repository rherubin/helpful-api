# Find-bugs report — 2026-08-11 (UTC)

## Critical bug found: yes

### Bug and impact
Paired Sit Session generation silently dropped Partner B’s completed prep after the pairing was soft-deleted. The creator could still generate, but the LLM ran in single-prep / single-device mode, so couple content was built from only one partner’s answers despite both preps existing in `prompt_session_preps`.

### Root cause
`buildPartnersForGeneration` resolved the second partner via `getPairingById`, which excludes soft-deleted pairings. On failure it kept only `created_by_user_id`, while `bothPrepsComplete` still counted both completed prep rows. `GET .../prep` had the same live-only lookup, so partner answers also disappeared from the creator’s prep view after unpair.

### Trigger
1. Accepted pairing; create paired prompt session; both partners complete prep
2. Soft-delete the pairing (`DELETE /api/pairing/:id`)
3. Creator still has access via `created_by_user_id`
4. Reset/retry `POST /api/prompt-sessions/:id/generate` (or generate after unpair when content was not yet saved)
5. Before fix: succeeded with a single-device generation prompt (partner prep discarded)
6. After fix: both partners’ prep answers are included; paired prompt shape preserved

### Fix and validation
- Resolve pairing for generation (and creator prep visibility) via `getPairingByIdIncludingDeleted` when the live lookup fails
- Fall back to other completed prep rows if the pairing row is gone entirely
- Refuse paired generate that would silently degrade to one prep when two completed preps exist
- Regression: `testGenerateKeepsPartnerPrepAfterPairingSoftDelete` in `tests/prompt-sessions-test.js`
