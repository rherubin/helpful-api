# Find-bugs report — 2026-08-14 (UTC)

## Critical bug found: yes

### Bug and impact
Live Sit Session / program LLM generation could fail after successful model responses whenever the JSON contained ordinary therapy language such as **"nervous system: …"** or **"override the urge…"**. Clients saw `generation_status=failed` / empty Bridge+Session despite a valid payload — significant user-facing breakage on the new psychoeducation-heavy Sit Session contract (and on Helpful/Hopeful program generation).

### Root cause
`BasePromptService.validateAIResponse` used bare `/system\s*:/i` and `/override/i` as “dangerous” patterns. Those substrings appear constantly in EFT/Gottman-style psychoeducation. The Sit Session generate prompt explicitly asks for nervous-system / science copy, so production responses were especially likely to trip the filter after paid retries.

### Trigger
1. Complete Sit Session prep (solo or paired) and call `POST /api/prompt-sessions/:id/generate` with a real LLM (not `TEST_MOCK_LLM`)
2. Model returns valid couple-shaped JSON whose psychoeducation mentions e.g. `nervous system: settle` or `override the urge to defend`
3. Before fix: `validateAIResponse` returns false → parse/security retries → persisted `generation_error` / failed generation
4. After fix: same copy passes; only line-start role markers / `override … instructions` jailbreaks are rejected

### Fix and validation
- Narrow role markers to start-of-line (`(?:^|[\n\r])\s*system\s*:`, same for assistant/human)
- Replace bare `/override/i` with `/override\s+(?:previous\s+)?instructions/i`
- Regression cases in `tests/security-test.js` for therapy copy vs jailbreak strings
- `TEST_MOCK_LLM=true npm run test:security` → **47/47**
