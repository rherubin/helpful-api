# Find-bugs report — 2026-08-10 (UTC)

## Critical bugs found: yes (3)

### 1. Regeneration poller deletes steps (and CASCADE messages) before successful generation
- **Location:** `routes/programs.js` `startRegenerationPoller` / `pollOnce`
- **Trigger:**
  1. Program has steps + user messages
  2. Ops sets `programs.regenerate_therapy_response = TRUE` (documented regen path)
  3. Poller clears the flag, **deletes all steps** (`messages` / contributions CASCADE via FK)
  4. Validation fails (`user_name` / `partner_name` missing) **or** LLM fails / returns no days
  5. Flag already cleared → no automatic retry; steps and chat history are gone
- **Impact:** Data loss (program steps + all step messages)
- **Why high confidence:** Delete-before-success ordering is explicit in code; FK `ON DELETE CASCADE` on `messages.step_id` is explicit; validation that can fail runs after delete
- **Fix:** CAS-claim flag; validate + generate first; `replaceProgramSteps` swaps DELETE+INSERT in a transaction only after a valid days payload

### 2. Sit Session generation resurrects `abandoned` / `complete` sessions
- **Location:** `models/PromptSession.js` `saveGeneratedContent`
- **Trigger:**
  1. Both preps complete → auto-generate (or `POST .../generate`) starts, CAS claim held
  2. Member `PATCH`es `status` to `abandoned` (or `complete`) while LLM is in flight
  3. Generation succeeds → `saveGeneratedContent` sets `status = 'bridge'`
  4. Session is no longer abandoned; client state is overwritten
- **Impact:** Silent overwrite of intentional terminal product state (correctness / unexpected resurrection)
- **Why high confidence:** `status = ?` with default `'bridge'` has no guard against terminal statuses; PATCH allows `abandoned`/`complete` concurrently with generation
- **Fix:** `status = IF(status IN ('complete','abandoned'), status, ?)`

### 3. Concurrent program generators can insert duplicate day steps
- **Location:** `routes/programs.js` `generateAndPersistProgramContent`; `models/ProgramStep.js` schema
- **Trigger:**
  1. `POST /api/programs` starts background generation (no steps yet)
  2. Client immediately `POST /api/programs/:id/therapy_response` (or double-fire)
  3. Both pass `hasProgramSteps` TOCTOU checks, both call LLM, both `createProgramSteps`
  4. Index on `(program_id, day)` was non-unique → duplicate day rows
- **Impact:** Data corruption (duplicate days); losing generator can also stamp a false `generation_error` over a successful program
- **Why high confidence:** No unique constraint; check-then-act is not atomic; follow-up path wrote `generation_error` without re-checking steps
- **Fix:** `UNIQUE (program_id, day)` + dedupe migration; `ER_DUP_ENTRY` treated as success; skip `generation_error` persist when steps already exist; empty/malformed days throw instead of returning `[]`
